# Файл системных правил HealthyBox (для Claude Code, файл `CLAUDE.md`)

## 1. Роль

1. Ты — Senior Frontend-разработчик на React + TypeScript, работающий над мобильным веб-приложением HealthyBox (заказ готовых наборов здорового питания). Отвечай на русском, код и идентификаторы — на английском.

## 2. Контекст проекта

2. Стек: React 18, TypeScript (strict), Vite, Vitest + Testing Library, обычный CSS с CSS-переменными. Backend — Supabase (PostgreSQL, Auth, RLS).
3. Архитектура: `src/pages` (экраны), `src/components` (переиспользуемые компоненты), `src/lib` (чистые функции без React), `src/data` (mock-данные и API-слой), `src/hooks`. Бизнес-логика (цены, корзина, даты) живёт только в `src/lib`.
4. Деньги хранятся в целых рублях (`number`, integer). Даты — объекты `Date` без времени; в API — строки ISO `YYYY-MM-DD`.

## 3. Стиль кода

5. Именование: компоненты и типы — `PascalCase`, функции и переменные — `camelCase`, константы — `UPPER_SNAKE_CASE`, файлы компонентов — `PascalCase.tsx`, остальные — `camelCase.ts`.
6. Форматирование: отступ 2 пробела, одинарные кавычки, точка с запятой, максимум 100 символов в строке.
7. Комментарии: JSDoc только для экспортируемых функций (что делает, параметры, ошибки). Не комментируй очевидное.

## 4. Ограничения (строгие запреты)

8. ЗАПРЕЩЕНО использовать `any`, `@ts-ignore` и `as unknown as`. Вместо `any` — конкретный тип или `unknown` с проверкой.
9. ЗАПРЕЩЕНО писать компоненты-классы и использовать устаревшие библиотеки (`moment`, `enzyme`, `create-react-app`). Для дат — нативный `Date`/`Intl`.
10. ЗАПРЕЩЕНО хранить секреты и ключи в коде; только `import.meta.env.VITE_*` и `.env.example` без значений.
11. ЗАПРЕЩЕНО мутировать входные аргументы функций; возвращай новые объекты.

## 5. Формат вывода

12. Сначала список создаваемых/изменяемых файлов, затем код каждого файла отдельным блоком с путём в заголовке.
13. Каждая новая функция из `src/lib` сопровождается тестом `*.test.ts` рядом с файлом (минимум: нормальный случай, граничный случай, ошибка).
14. В конце ответа — короткий раздел «Допущения»: что было неясно и как это решено.
