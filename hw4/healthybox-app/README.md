# HealthyBox

Мобильное веб-приложение для заказа готовых наборов здорового питания (MVP): каталог из 6 рационов (Лёгкий, Баланс, Масса, Вегетарианский, Низкоуглеводный, Спорт), детальное меню по дням, корзина с выбором даты первой доставки, вход и регистрация, оформление заказа, роли «пользователь» и «администратор».

## Стек

React 18, TypeScript (strict), Vite, Vitest + Testing Library, обычный CSS (mobile-first), Supabase (backend, опционально).

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 103 теста
npm run typecheck
npm run build
```

Без настроенного backend приложение работает на mock-данных. Чтобы увидеть состояние ошибки сети, откройте `/?fail=1`.

## Подключение Supabase

1. Создайте проект в Supabase и выполните `hw5/supabase/migrations/0001_init.sql`, `0002_rls.sql`, `0003_grants.sql`, `0004_roles.sql`, `0005_order_status_guard.sql`, …, `0009_more_plans.sql`, `0006_profile_details.sql`, `0007_order_address.sql`, `0008_view_address.sql`, затем `seed.sql`.
2. Скопируйте `.env.example` в `.env` и укажите `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` (только публичный ключ; секретный ключ `sb_secret_…` / `service_role` во фронтенд не добавляется). В репозитории лежит `.env` тестового проекта, поэтому после клонирования достаточно `npm install`.
3. Перезапустите `npm run dev`: каталог будет загружаться из базы.

## Вход и роли

- Регистрация и вход по email и паролю (Supabase Auth). Если в проекте включено подтверждение почты, после регистрации нужно подтвердить email.
- **Пользователь**: ведёт профиль (имя, телефон, адрес доставки), оформляет заказы, видит их детализацию (состав, цены, суммы), отменяет оформленный заказ, скачивает свои заказы в CSV.
- **Администратор**: открывает вкладку «Свод»: ключевые цифры, графики (выручка по дням и по рационам, с подсказками при наведении), разбивка по статусам, рационам и клиентам и общий лист всех строк заказов (сортировка по клику на заголовок, фильтр по статусу, поиск, строка итогов, выгрузка в CSV). Также видит все заказы с детализацией и клиентом, фильтрует по статусу и ищет по email или номеру, видит сводку (число заказов, выручка, средний чек) и популярность рационов, меняет статус заказов, меняет роли пользователей, редактирует цены рационов, скачивает заказы и пользователей в CSV.
- Адрес доставки подставляется в корзину из профиля, его можно поправить; он сохраняется в заказе, показывается в карточке заказа и попадает в CSV.
- CSV открывается в Excel (кодировка UTF-8 с BOM, разделитель `;`); ячейки, похожие на формулы, экранируются.
- Первого администратора назначьте в SQL Editor: `update public.profiles set role = 'admin' where email = '<почта>';`.
- Скрытие экранов в интерфейсе — только удобство; доступ ограничивает RLS в базе (`hw5/backend_documentation.md`, раздел «Роли»).
