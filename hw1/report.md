# 1. Описание задачи и требований

## Задача

Разработать MVP приложения HealthyBox: каталог готовых наборов питания, детальное меню по дням, корзина с выбором даты первой доставки, затем backend и CI/CD. Это реальная задача для курса: на ней выполняются ДЗ 2–6.

## Ключевые требования к инструменту

| Требование | Значение | Влияние на выбор |
|---|---|---|
| Сложность | Средняя: несколько экранов, бизнес-логика цен и дат, тесты, SQL-миграции, CI | Нужна работа с несколькими файлами сразу и запуск тестов |
| Доступ к локальным файлам | Обязателен: проект и документы ДЗ лежат на диске | Cloud-агенты в браузере неудобны |
| Безопасность данных | Нельзя отправлять ключи и персональные данные; код учебный, но будет в публичном репозитории | Нужен контроль над тем, какие файлы видит агент |
| Бюджет | Ограничен (студент) | Важна предсказуемая цена |
| Срок | Несколько недель, часть работы — отладка и тесты | Нужен агент, который сам запускает тесты и сборку |

# 2. Анализ инструментов

## Сравниваемые инструменты

| Тип | Инструмент | Как работает |
|---|---|---|
| Cloud-агент | Bolt.new | Генерация и запуск веб-приложения целиком в браузере, проект живёт в облаке |
| Cloud-агент | Lovable | Генерация веб-приложения по описанию, интеграция с Supabase и GitHub |
| IDE-агент | Cursor | Редактор на базе VS Code со встроенным агентом, видит весь проект |
| CLI/IDE-агент | Claude Code | Агент в терминале и в десктопном приложении, работает в папке проекта, сам запускает команды |

Различие типов: Cloud-агент создаёт и хранит проект на стороне сервиса и ограничен его средой исполнения. IDE-агент работает внутри редактора над локальными файлами. CLI-агент работает в терминале в папке проекта и может запускать любые локальные команды (тесты, сборка, git).

## Критерии

1. Доступ к контексту проекта: насколько агент видит весь проект и внешние файлы.
2. Скорость генерации кода.
3. Качество кода: корректность, соответствие стеку, тестируемость.
4. Стоимость использования (5 — дешевле).
5. Требования к безопасности данных (5 — меньше рисков для данных проекта).
6. Удобство интеграции в рабочий процесс: git, тесты, CI, MCP.

## Обоснование оценок

> **Важно о методе.** Практически проверен только Claude Code (на нём выполнены все ДЗ). Оценки Bolt.new, Lovable и Cursor — экспертные, на основе публичной документации и общеизвестных свойств инструментов, а не собственных замеров. Тарифы меняются, поэтому актуальные цены нужно проверять на сайтах сервисов.

- **Bolt.new и Lovable (контекст 2, безопасность 2).** Проект и код находятся в облаке сервиса, локальные файлы агенту недоступны. Скорость первой версии интерфейса высокая (5), но качество среднее (3): быстро получается демо, сложнее поддерживать тесты и нестандартную логику. Lovable интеграцией с GitHub и Supabase удобнее (3), чем Bolt.new (2).
- **Cursor (контекст 5, интеграция 5).** Индексирует весь проект, работает в привычном редакторе, поддерживает файл правил и MCP. Скорость хорошая (4) за счёт встроенных автодополнений. Безопасность средняя (3): код отправляется на серверы сервиса, есть настройки приватности.
- **Claude Code (контекст 5, качество 5).** Видит всю папку проекта, читает любые файлы, сам запускает тесты, сборку и `npm audit`, исправляет ошибки по их выводу. Скорость ниже (3): многошаговая работа с проверками занимает больше времени, чем одно автодополнение. Стоимость выше (2): оплата идёт по подписке или по токенам, при большой работе над проектом расход заметный. Безопасность средняя (3): код отправляется модели, но агент работает с правами пользователя и запускается в выбранном пользователем режиме разрешений.

Для российских пользователей отдельным критерием может быть доступность сервиса и соответствие требованиям к хранению данных. Для этого в курсе рассматриваются GigaCode и YandexGPT, а также on-premise развёртывание моделей (DeepSeek, Qwen). Для учебного проекта без персональных данных этот критерий не определяющий, поэтому в таблицу он не включён.

# 3. Выбор инструмента

## Выбор: Claude Code

## Ключевые факторы

1. **Локальные файлы и сквозной контекст.** Для ДЗ нужны документы `.docx`, `.md`, код, SQL и конфигурации в одной папке. Cloud-агенты такую работу не поддерживают.
2. **Самостоятельная проверка результата.** Агент сам запускает `tsc`, `vitest`, `vite build`, `npm audit` и исправляет ошибки по выводу. В ДЗ 6 так были найдены и закрыты 6 уязвимостей зависимостей, а после обновления Vitest исправлена ошибка типов в `vite.config.ts`.
3. **Качество на многошаговых задачах.** Проект включает код, тесты, SQL-миграции, CI и документы, которые должны быть согласованы между собой.
4. **Правила проекта.** Файл `CLAUDE.md` задаёт стек и запреты (ДЗ 2), и агент применяет их на каждой задаче.
5. **Практическая проверка.** Этот инструмент единственный, работу которого можно подтвердить логами, тестами и скриншотами.

## Честное замечание о выборе

По сумме баллов Cursor опережает Claude Code (24 против 22). Разница в два балла при экспертных оценках находится в пределах погрешности. Решающими стали пункты 2 и 5: автономный запуск проверок и наличие доказательств работы.

## Альтернативы и почему не подошли

| Вариант | Почему не выбран |
|---|---|
| Bolt.new | Проект живёт в облаке, нет доступа к локальным документам, слабая поддержка тестов и CI |
| Lovable | Хорош для быстрого прототипа интерфейса, но ограничивает контроль над кодом и структурой, нет работы с локальными файлами |
| Cursor | Близкая альтернатива: лучше по скорости и интеграции в редактор; уступает в автономном выполнении многошаговых задач с проверками. Может быть выбран, если важнее работа внутри редактора |

# 5. Примеры работы с инструментом

## Задача

Реализовать логику корзины: добавление набора с датой первой доставки (не ранее чем через 2 дня), изменение количества, удаление позиции при количестве 0, подсчёт итога.

## Использованный промпт

> Реализуй модуль корзины для HealthyBox: функция добавления набора с проверкой даты доставки (не ранее чем через 2 дня от сегодня), функция изменения количества (при 0 позиция удаляется), подсчёт итоговой суммы. Функции чистые, без мутации входных данных. Напиши тесты.

## Ход работы

| Параметр | Значение |
|---|---|
| Итераций с агентом | 1: тесты прошли с первого запуска |
| Файлов создано | 2 (`cart.js`, `cart.test.js`) |
| Тестов | 5, все прошли |
| Время выполнения тестов | около 76 мс |

## Результат (фрагмент)

```js
function addToCart(cart, item, deliveryDate, today = new Date()) {
  if (!isDeliveryDateAllowed(deliveryDate, today)) {
    throw new RangeError('Дата доставки не ранее чем через 2 дня');
  }
  const key = `${item.id}:${item.period}:${deliveryDate.toISOString().slice(0, 10)}`;
  const existing = cart.find((l) => l.key === key);
  if (existing) return cart.map((l) => (l.key === key ? { ...l, qty: l.qty + 1 } : l));
  return [...cart, { key, ...item, deliveryDate, qty: 1 }];
}
```

## Замечание по качеству

В демо-версии ключ позиции строится через `toISOString()`, который переводит дату в UTC. В часовых поясах восточнее UTC это может сдвинуть дату на предыдущий день. Поэтому в основном проекте (ДЗ 4, `src/lib/cart.ts`) ключ строится по локальной дате. Демо-код оставлен как есть, чтобы показать реальный результат первой итерации.

# 6. Выводы и рекомендации

## Выводы

1. Cloud-агенты подходят для быстрого прототипа интерфейса, но не для проекта с локальными документами, тестами и CI.
2. IDE- и CLI-агенты дают полный контекст проекта. Главное различие между ними — Cursor удобнее в редакторе, Claude Code лучше в автономном выполнении цепочки «написать, запустить, исправить».
3. Для проекта HealthyBox выбран Claude Code, при этом Cursor остаётся равноценной альтернативой.

## Рекомендации

- Начинать новый проект с файла правил (`CLAUDE.md` или `.cursorrules`): это заметно повышает предсказуемость результата (подтверждено в ДЗ 2).
- Просить агента писать тесты вместе с кодом и запускать их до сдачи работы.
- Не передавать агенту ключи и персональные данные; секреты хранить только в `.env`, а в репозиторий добавлять `.env.example`.
- Проверять результат самостоятельно: агент может ошибаться в деталях (пример с UTC-датой выше).
- Перед окончательным выбором инструмента для команды провести собственный замер на одной и той же задаче, а не опираться только на экспертные оценки.
