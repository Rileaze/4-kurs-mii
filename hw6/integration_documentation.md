## 1. CI/CD

### Платформа и этапы

GitHub Actions, файл `.github/workflows/ci.yml`. Запуск: `push` и `pull request` в ветку `main`.

| Job | Этап | Команда | Условие |
|---|---|---|---|
| quality | Установка зависимостей | `npm ci` | всегда |
| quality | Проверка типов (контроль качества кода) | `npm run typecheck` | всегда |
| quality | Тесты | `npm test` | всегда |
| quality | Аудит зависимостей | `npm audit --audit-level=high` | всегда; падает при высоких и критических уязвимостях |
| quality | Сборка | `npm run build` | всегда; ключи берутся из secrets |
| quality | Артефакт | `upload-artifact` (`dist`) | всегда |
| deploy | Деплой на Vercel | `npx vercel deploy --prod` | только `push` в `main` после успешного `quality` |
| deploy | Health check | `curl` к `/health.json`, 5 попыток через 10 с | после деплоя |

Отдельного линтера (ESLint) в проекте нет. Функцию проверки качества выполняет строгая проверка типов TypeScript. ESLint и Prettier рекомендуется добавить.

### Секреты репозитория

Задаются в GitHub → Settings → Secrets and variables → Actions:

| Секрет | Назначение |
|---|---|
| `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` | Сборка с backend (публичные значения) |
| `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID` | Деплой на Vercel |
| `APP_URL` | Адрес сайта для health check |

### Как проверить пайплайн

1. Создайте репозиторий и отправьте код (команды в `development_report.md` ДЗ 4).
2. Создайте проект на Vercel и добавьте секреты.
3. Сделайте тестовый коммит в `main` и проверьте вкладку Actions.

## 3. OAuth2 (Google)

Реализация: `signInWithGoogle` в `src/data/supabaseApi.ts` вызывает `auth.signInWithOAuth({ provider: 'google' })`. Поток обрабатывает Supabase Auth, секрет клиента хранится в Supabase, а не в приложении.

Что нужно сделать вам:

1. Google Cloud Console → APIs & Services → Credentials → Create OAuth client ID (Web application). В **Authorized redirect URIs** укажите callback Supabase: `https://<project>.supabase.co/auth/v1/callback`.
2. Скопируйте Client ID и Client Secret.
3. Supabase → Authentication → Providers → Google: включите и вставьте значения.
4. В Authentication → URL Configuration укажите Site URL и Redirect URLs.
5. Добавьте кнопку «Войти через Google», вызывающую `signInWithGoogle` (в интерфейсе её пока нет).

Проверки после настройки: успешный вход, отмена на странице Google (приложение должно показать сообщение «Не удалось войти через Google»), получение данных пользователя (`supabase.auth.getUser()`).

## 4. Аналитика (Яндекс.Метрика)

Реализация: `src/lib/analytics.ts`, функция `track(event, params)` отправляет цель через `ym(counterId, 'reachGoal', ...)`. Ошибки счётчика (например, блокировка рекламным фильтром) игнорируются, приложение не ломается. Без `VITE_YM_COUNTER_ID` функция ничего не делает.

События:

| Событие | Когда | Подключено в UI |
|---|---|---|
| `add_to_cart` | Подтверждена дата и набор добавлен в корзину | Да |
| `change_cart_qty` | Нажаты «+» или «-» в корзине | Да |
| `view_catalog`, `change_period`, `open_set`, `open_dish` | Определены в типе | Нет, вызовы не добавлены |

Что нужно сделать вам: создать счётчик в Яндекс.Метрике, вставить стандартный код счётчика в `index.html` (вместо номера подставьте свой), записать номер в `.env` как `VITE_YM_COUNTER_ID`, настроить цели с названиями событий из таблицы. Домен `mc.yandex.ru` уже разрешён в CSP.

Тесты (`analytics.test.ts`): без настройки вызовов нет; при настройке цель отправляется с параметрами; ошибка счётчика не пробрасывается.

## 6. Логирование

Реализация: `src/lib/logger.ts`.

- Формат: одна JSON-строка на запись: `{"ts","level","msg", ...контекст}`.
- Уровни: `info`, `warning`, `error` (выводятся в `console.info/warn/error`).
- Маскирование: значения полей `password`, `token`, `authorization`, `apikey`, `email` заменяются на `[REDACTED]`.
- Защита от подмены: поля контекста не могут переопределить `level` и `msg`.
- Подключено: ошибка загрузки каталога (`catalog load failed`).
- Централизованное хранение для браузерных логов не настроено. Варианты: Sentry или отправка на endpoint сбора логов.

Пример записи:

```
{"error":"Не удалось загрузить данные","ts":"2026-10-11T15:04:05.120Z","level":"error","msg":"catalog load failed"}
```
