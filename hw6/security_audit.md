# Отчёт по аудиту безопасности

## Область проверки

Проект `hw4/healthybox-app` (React + TypeScript + Supabase-клиент) и SQL-политики `hw5/supabase`. Проверка выполнена агентом Claude Code с запуском инструментов; статический анализ OWASP — по коду вручную и командами `grep`. Специализированные сканеры кода (Semgrep, CodeQL, Snyk) не запускались.

## 1. Аудит зависимостей

Команда: `npm audit`.

### До исправления

| Пакет | Серьёзность | Проблема | Тип зависимости |
|---|---|---|---|
| `tinypool` (через `vitest`) | Критическая (2 записи) | Prototype pollution в параметрах воркера, приводящий к удалённому выполнению кода (RCE) | dev |
| `esbuild` (через `vite`) | Средняя | Любой сайт может отправлять запросы к dev-серверу и читать ответы | dev |
| `@vitest/mocker` (через `vitest`) | Средняя | Path traversal и чтение произвольных файлов через подмену мока | dev |
| `vite-node`, `vite`, `vitest` | Транзитивно | Остальные записи отчёта: зависят от уязвимых версий выше | dev |

Итого: **6 уязвимостей** (3 средних, 1 высокая, 2 критические).

Оценка риска: все пакеты — зависимости разработки, в production-сборку (`dist`) они не попадают. Риск относится к машине разработчика и CI: например, открытие вредоносного сайта при запущенном `npm run dev`.

### Исправление

Обновлены `vite` до 8.3.4, `vitest` до 5.0.3, `@vitejs/plugin-react` до 6.1.2 (мажорные версии, команда `npm i -D vite@latest vitest@latest @vitejs/plugin-react@latest`).

Последствия обновления:

1. Сборка упала с ошибкой `TS2769: 'test' does not exist in type 'UserConfigExport'`. Причина: в новой версии тип `defineConfig` из `vite` не содержит поле `test`. Исправление: импорт `defineConfig` из `vitest/config`.
2. После исправления: типы, сборка и все тесты проходят.

### После исправления

```
npm audit
found 0 vulnerabilities
```

Тесты после обновления: 21 из 21 пройден (в итоговой версии 27 из 27).

## 3. Защита от распространённых атак

| Атака | Мера | Где |
|---|---|---|
| XSS | Нет опасных API вставки HTML; Content-Security-Policy ограничивает источники скриптов и соединений | `vercel.json` |
| Clickjacking | `X-Frame-Options: DENY` и `frame-ancestors 'none'` | `vercel.json` |
| MIME sniffing | `X-Content-Type-Options: nosniff` | `vercel.json` |
| Утечка Referer | `Referrer-Policy: strict-origin-when-cross-origin` | `vercel.json` |
| CSRF | Токен передаётся заголовком `Authorization`, а не cookie, поэтому классический CSRF неприменим | Supabase-клиент |
| SQL-инъекция | Параметризованные запросы PostgREST, RLS | БД |
| Подмена цены | Серверный расчёт `unit_price` | Триггер БД |

## 4. Оставшиеся риски и рекомендации

1. **Сессия в localStorage.** Клиент Supabase по умолчанию хранит токены в `localStorage`; при успешной XSS их можно украсть. Снижение риска: строгий CSP (добавлен), отсутствие вставки HTML, короткий срок жизни токена. Для повышенных требований — хранение сессии в httpOnly-cookie через серверный слой.
2. **CSP разрешает `style-src 'unsafe-inline'`.** Приложение не использует inline-стили в разметке, поэтому директиву можно ужесточить после проверки в браузере. Заголовки не проверялись на задеплоенном сайте.
3. **Домен `mc.yandex.ru` в CSP** нужен только при подключении Яндекс.Метрики; если она не используется, его следует убрать.
4. **RLS не проверена на реальной БД.** Выполнить чек-лист из `backend_documentation.md` (проверки 2, 5, 7, 8, 9).
5. **Включить в Supabase:** подтверждение email, ограничение частоты запросов к Auth, MFA для аккаунтов администраторов.
6. **Сканеры.** Добавить в CI Semgrep или CodeQL и автоматические обновления зависимостей (Dependabot).
7. **Ключи.** Если `service_role` когда-либо попадёт в репозиторий, его нужно немедленно перевыпустить.
