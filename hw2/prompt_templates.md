# Библиотека промпт-шаблонов (структура RTCF)

Каждый шаблон содержит блоки Role, Task, Context, Format. В угловых скобках указаны поля для подстановки.

## 1. Генерация компонента или функции

```
### Role
Ты — Senior Frontend-разработчик на React + TypeScript.

### Task
Создай <компонент / функцию> <название>, которая <что делает>.

### Context
- Стек и правила проекта: см. CLAUDE.md.
- Входные данные: <типы и пример>.
- Поведение в граничных случаях: <пустые данные, ошибки>.
- Файл должен лежать в <путь>.

### Format
1. Список создаваемых файлов.
2. Код каждого файла отдельным блоком с путём.
3. Тест рядом с файлом.
4. Раздел «Допущения».
```

**Пример использования:**

```
### Role
Ты — Senior Frontend-разработчик на React + TypeScript.

### Task
Создай функцию calcSetPrice, которая считает цену набора за день или неделю.

### Context
- Стек и правила проекта: см. CLAUDE.md.
- Вход: period ('day' | 'week'), dayPrice (целые рубли). Неделя = 7 дней со скидкой 10%.
- Некорректная цена (0, дробь) — RangeError.
- Файл: src/lib/pricing.ts.

### Format
Список файлов, код с путями, тест рядом, раздел «Допущения».
```

## 2. Рефакторинг кода

```
### Role
Ты — Senior разработчик, специализирующийся на рефакторинге без изменения поведения.

### Task
Улучши структуру и читаемость кода ниже, не меняя внешнее поведение.

### Context
- Код: <вставить код>.
- Проблемы, которые заметны: <дублирование, длинная функция, сложные условия>.
- Существующие тесты: <путь>. Они должны проходить без изменений.

### Format
1. Список проблем (по одной строке).
2. Изменённый код.
3. Что изменилось и почему (список).
4. Результат запуска тестов.
```

**Пример использования** (ситуация из ДЗ 4: api.ts лениво подключает модуль Supabase, а ApiError нужен обоим файлам):

```
### Role
Ты — Senior разработчик, специализирующийся на рефакторинге без изменения поведения.

### Task
Убери циклическую зависимость между api.ts и supabaseApi.ts.

### Context
- supabaseApi.ts импортирует ApiError из api.ts, а api.ts динамически импортирует supabaseApi.ts.
- src/pages/CatalogPage.test.tsx импортирует ApiError из api.ts, это должно продолжать работать.

### Format
Список проблем, изменённые файлы, объяснение, результат npm test.
```

## 3. Написание тестов

```
### Role
Ты — инженер по тестированию, пишешь тесты на Vitest и Testing Library.

### Task
Напиши тесты для <функции / компонента>.

### Context
- Код: <вставить или указать путь>.
- Требуемые случаи: нормальный, граничный, ошибочный.
- Нельзя использовать any, нельзя полагаться на текущую дату (передавай её параметром).

### Format
Один файл *.test.ts(x) рядом с исходным. Названия тестов описывают поведение. В конце — таблица «случай → что проверяется».
```

**Пример использования:**

```
### Role
Ты — инженер по тестированию, пишешь тесты на Vitest и Testing Library.

### Task
Напиши тесты для функций addToCart и changeQty из src/lib/cart.ts.

### Context
- Правило: дата доставки не ранее чем через 2 дня. Сегодняшнюю дату передавай параметром.
- Случаи: добавление, повтор той же позиции, слишком ранняя дата, увеличение количества, удаление при 0.

### Format
Файл src/lib/cart.test.ts и таблица «случай → что проверяется».
```

## 4. Исправление ошибок

```
### Role
Ты — Senior разработчик, диагностируешь ошибки по симптомам.

### Task
Найди причину и исправь ошибку.

### Context
- Ожидаемое поведение: <...>.
- Фактическое поведение: <...>.
- Сообщение об ошибке или лог: <вставить>.
- Шаги воспроизведения: <...>.
- Релевантные файлы: <пути>.

### Format
1. Причина (1–2 предложения).
2. Минимальное исправление (diff).
3. Тест, который падал до исправления и проходит после.
4. Как проверить вручную.
```

**Пример использования** (реальная ошибка из ДЗ 6 после обновления Vitest):

```
### Role
Ты — Senior разработчик, диагностируешь ошибки по симптомам.

### Task
Найди причину и исправь ошибку сборки.

### Context
- Ожидаемое: npm run build завершается успешно.
- Фактическое: vite.config.ts(7,3): error TS2769: 'test' does not exist in type 'UserConfigExport'.
- Шаги: обновить vitest до 5.x и запустить npm run build.
- Файл: vite.config.ts.

### Format
Причина, diff, проверка сборки.
```

## 5. Декомпозиция сложной задачи

```
### Role
Ты — тимлид, который разбивает задачу на небольшие проверяемые шаги.

### Task
Разбей задачу «<описание>» на последовательные шаги.

### Context
- Стек и правила: CLAUDE.md.
- Уже готово: <список>.
- Ограничения: <срок, бюджет, что не входит в объём>.

### Format
Таблица: № шага | что делаем | файлы | как проверить результат | зависит от шага. Не более 8 шагов. Каждый шаг можно выполнить за один запрос к агенту.
```

**Пример использования:**

```
### Role
Ты — тимлид, который разбивает задачу на небольшие проверяемые шаги.

### Task
Разбей задачу «корзина с выбором даты первой доставки» на шаги.

### Context
- Стек: React + TypeScript, правила в CLAUDE.md.
- Готово: типы и mock-данные.
- Правило: дата доставки не ранее чем через 2 дня; при количестве 0 позиция удаляется.

### Format
Таблица: № шага | что делаем | файлы | как проверить | зависит от шага. До 8 шагов.
```
