# Цепочка промптов (Chain-of-Thought)

## Задача

Реализовать в HealthyBox корзину с выбором даты первой доставки: набор добавляется через календарь (даты ближе чем через 2 дня недоступны), в корзине можно менять количество, при 0 позиция удаляется, итог пересчитывается.

Задача сложная: в ней сочетаются бизнес-правила, состояние, несколько экранов и тесты. Поэтому она решалась по шагам: каждый шаг опирается на результат предыдущего и проверяется отдельно.

## Шаг 1. Модель данных и чистая логика

Промпт:

```
Role: Senior Frontend на React + TypeScript (правила в CLAUDE.md).
Task: создай типы Plan, Dish, CartItem и функции calcSetPrice, addToCart, changeQty, cartTotal.
Context: деньги в целых рублях; неделя = 7 дней со скидкой 10%; дата доставки не ранее чем через 2 дня; при количестве 0 позиция удаляется; сегодняшняя дата передаётся параметром.
Format: файлы src/types.ts, src/lib/pricing.ts, src/lib/cart.ts и тесты рядом.
```

Результат: созданы типы и две библиотеки, 11 тестов (5 на цены, 6 на корзину). Все прошли с первого запуска.

## Шаг 2. Данные и компоненты

Промпт:

```
Role: Senior Frontend на React + TypeScript.
Task: создай mock-данные (3 рациона, 7 дней по 4 приёма пищи) и компоненты PeriodToggle, PlanCard, DatePickerModal, StateViews.
Context: используй функции из шага 1; состояния loading, error, empty; календарь показывает 14 дней, первые 2 недоступны; кнопки не меньше 44 px.
Format: список файлов и код с путями.
```

Результат: компоненты и данные созданы, `tsc --noEmit` без ошибок.

## Шаг 3. Экраны и сборка потока

Промпт:

```
Role: Senior Frontend на React + TypeScript.
Task: собери экраны CatalogPage, SetPage, CartPage и App с переходами каталог → набор → корзина.
Context: корзина хранится в состоянии App; срок (день/неделя) сохраняется из каталога при открытии набора; в SetPage календарь открывается по кнопке «Добавить в корзину».
Format: список файлов и код с путями.
```

Результат: работающий поток. Добавлен CSS (mobile-first, точки перелома 640 и 960 px).

## Шаг 4. Тесты потока и состояний

Промпт:

```
Role: инженер по тестированию (Vitest + Testing Library).
Task: напиши тесты состояний каталога (loading, success, error с повтором, empty), календаря и сквозной поток добавления в корзину.
Context: загрузку данных передавай в CatalogPage параметром load, чтобы подменять её в тестах.
Format: файлы *.test.tsx рядом с исходниками.
```

Результат: суммарно 18 тестов, все проходят с первого запуска.

## Шаг 5. Проверка

Промпт:

```
Role: инженер по качеству.
Task: запусти typecheck, тесты, сборку и npm audit, составь список проблем.
Format: вывод команд и список находок.
```

Результат: typecheck, тесты и сборка проходят. `npm audit` нашёл 6 уязвимостей в dev-зависимостях (подробнее в ДЗ 6).

## Что оказалось полезным

- Разделение на шаги дало проверяемые промежуточные результаты: после каждого шага запускались `tsc` и тесты.
- Передача сегодняшней даты параметром сделала логику даты детерминированной и тестируемой.
- Правила из `CLAUDE.md` не нужно было повторять в каждом промпте.

## Сложности

На шагах 1–4 ошибок не возникло. Это нужно учитывать: задача хорошо описана и мала, поэтому цепочка отработала без исправлений. Реальные исправления понадобились позже, при обновлении зависимостей (ДЗ 6).
